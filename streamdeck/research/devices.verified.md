## 0. Changes from the first draft

Corrections:

1. **Studio does work with the Stream Deck app (USB mode).** The draft said Studio "runs on
   Companion and does not support Stream Deck app profiles", so don't generate one. Elgato's Studio
   product FAQ says: "In USB mode, it'll work with the Stream Deck app" [C]. The Marketplace profile
   docs still say Studio "does not currently support Stream Deck app profiles" [C], and the manifest
   schema accepts `Profiles[].DeviceType: 10` [C]. So a Studio profile is **optional and untested**,
   not ruled out.
2. **7.x exports use a new file layout (Version 3.0), not 2.0.** Real exports from Stream Deck
   7.3.1 and 7.4.0 (Windows) have a root `package.json`
   (`AppVersion`, `DeviceModel`, `FormatVersion: 1`, `OSType`, `OSVersion`, `RequiredPlugins`,
   `DeviceSettings`) and `Profiles/<UUID>.sdProfile/manifest.json` with `"Version": "3.0"`. Page
   folders are named with upper-case UUIDs, and `Device.UUID` is a random UUID [R]. Elgato's own
   plugin samples still ship the older layout (`<UUID>.sdProfile/manifest.json`, `"Version": "2.0"`,
   page folders with 27-character encoded names) [C]. Both exist. The draft hadn't checked 7.x exports.
3. **`20GBX9901` (+ XL) evidence downgraded to weak [R].** The draft's "seen in real profile
   files" was a hand-written **test fixture** in `verygoodplugins/streamdeck-mcp`. Its comment refers
   to a real user's trial run, but the file isn't an export. The only other file with
   `20GBX9901` is Aputure's Sidus Link Pro pack, which its README says is "encoded to match a genuine
   Stream Deck macOS app export", i.e. generated by a tool. That same pack writes `20GBC9901` for
   the Stream Deck +, contradicting Elgato's `20GBD9901` (Elgato sample, HID docs, and a real on-disk
   + profile), and its + XL profile fills only 4 of the 6 dials. Elgato's HID page lists `20GBD9901`
   for the + XL, which still looks like a copy error. `20GBX9901` (matching retail SKU `10GBX9901`)
   remains the best guess, but **no real export or Elgato source confirms it**.
4. **Galleon 100 SD grid is 3 columns × 4 rows.** The SDK enum says "3 x 4", in its usual
   columns × rows order [C]. `@elgato-stream-deck/core` builds it as 3 columns × 4 rows of 160 px keys
   on a 720 px wide portrait panel [R], and reviews call it a 3×4 numpad replacement [R]. The draft
   had this right but missed that **Elgato's profile docs table (rows × columns everywhere else)
   also says "3 x 4"**, so that table contradicts the SDK. Trust the SDK. The "5-inch display" is
   the whole 1280×720 panel behind the keys and screen [C/R]; the visible screen strip above the keys
   is about 720×384 [R]. The dials sit above the screen [R].
5. **Neo Infobar actions do get `willAppear`, `willDisappear` and `sendToPlugin`.** The draft
   listed only settings, resources, Property Inspector and `titleParametersDidChange`. They get no
   key, dial or touch input events [C].
6. **Virtual Stream Deck isn't labelled beta on the hardware page.** Only the URL slug of the
   linked overview (`virtual-stream-deck-beta-overview`) says beta; no text on either page does [C].
   VSD needs Stream Deck 7.0+ and **Windows 11 (64-bit) or later** [C].
7. **Stream Deck Mobile "two keypads on iPad, up to 128 keys" isn't confirmed.** Elgato says you
   can run "multiple" keypads at once and that the "number of keypads depends on device and
   settings" [C]. Free: 6 keys. Pro: up to 64 keys and custom layouts. Up to 10 extra pages. Needs
   Stream Deck 6.3+ [C].

Gaps filled:

8. **Icon pack images must be 144 × 144 px** (static: SVG, PNG, JPEG; animated: GIF, WEBP;
   10–20 fps, ≤5 s, preferably ≤1 MB; file name ≤80 characters). "You do not need to provide
   different sized images for different Stream Deck devices" [C, icon pack docs].
9. **Plugin image rules** [C, plugin guidelines]: a manifest state image may be an animated GIF, but
   animated images "cannot be used when programmatically updating actions". `setImage` takes a
   single image, so send the high-DPI size. **Limit programmatic updates to 10 per second** per key.
   Key art: 72×72, plus 144×144 for high DPI when rasterised; SVG is recommended.
10. **A `"Neo"` controller forces `Software.MinimumVersion: "7.6"`.** In the manifest schema,
    every `MinimumVersion` below 7.6 limits `Controllers` to Encoder/Keypad (at most 2 items) [C].
    The `MinimumVersion` enum runs 6.4 … 7.6 [C].
11. **Model strings follow the exporting hardware, not the device type.** Real exports carry
    `20GAT9902` (XL 2022; 12 files), `20GAA9902` (2019 15-key, device UUID with PID 109 = 0x006D) and
    `20GBA9901` (MK.2, from a 7.3.1 export) [R]. One `DeviceType` therefore has several Model strings.
12. **Dial slots in profiles are `"<dial>,0"`.** Real Stream Deck + pages put dial actions in the
    `Encoder` controller at `0,0` … `3,0` [R]. + XL should be `0,0` … `5,0` [I].
13. **Release notes (help.elgato.com still returns 403; dates are from search snippets) [R]:**
    7.2.0 (6 Jan 2026) added Galleon; 7.2.1 (27 Jan 2026) shipped a default Galleon profile;
    7.3.0 (3 Mar 2026) added + XL and fixed the Galleon dropping back to "hardware mode". 7.6
    (22 Sept 2026) updated Pedal and + XL firmware [C, Elgato article].
14. **7.6 note that matters for Hotkey-based profiles:** "(Windows) Fixed an issue, introduced in
    7.5.1, where items could not be dragged from File Explorer … This change also means hotkeys may
    not reach elevated processes, such as some games, again." [C]

Confirmed unchanged: the DeviceType enum 0–13, all key and strip pixel sizes, the 200×100
encoder canvas on + and + XL, Neo Infobar 232×50, the `deviceDidConnect` shape, the official
sample Model strings, the Voyager key-count conflict, and the "38 keys" typo for the + XL.

Not re-checked (not build-critical): the commit hashes in the draft, Network Dock SKU and date,
Mini Discord Edition date, and release years of pre-2022 models.

## 1. Short version (what the generator needs)

- **`DeviceType`** runs **0–13**: 11 Virtual Stream Deck, 12 Galleon 100 SD, 13 Stream Deck + XL.
  It's the same in the GitHub source, npm 0.6.0 and the live schema [C].
- **Key art:** draw at **144×144** (or SVG). Icon packs **must** be 144×144 [C]. Plugin manifest
  images are 72×72 with 144×144 @2x [C]. `setImage` takes one image, so send 144×144 or SVG [C].
  The app scales to each device (72 to 160 px native) [C].
- **Animation:** icon packs may hold GIF/WEBP (10–20 fps, ≤5 s) [C]. Manifest state images may be
  GIF [C]. `setImage` can't animate; frame-by-frame `setImage` is limited to **10 calls/s** [C].
- **Dial / touch strip:** one **200×100** layout per dial on Stream Deck + (4) and + XL (6).
  Backgrounds are 200×100, plus 400×200 @2x. Plugins can't draw across the whole strip [C].
- **Neo Infobar:** 232×50 layout, `"Controllers": ["Neo"]`, needs Stream Deck **7.6** (set
  `MinimumVersion: "7.6"`). Display only, with no input events. Set the layout on every
  `willAppear` [C].
- **Profiles bundled in a plugin are matched by `DeviceType`** in the plugin manifest [C]. Generate
  one per type. Use the Model strings from Elgato's samples where they exist: `20GAA9901`,
  `20GAI9901`, `20GAT9901`, `VSD2/WiFi`, `20GBD9901` and `20GBJ9901` [C]. Use `20GBX9901` for type 13
  [R-weak], and test on hardware.
- **Pick one profile format** (see the profile-format research, `profiles.md`). The 2.0 layout is what Elgato's bundled
  samples use [C]. The 3.0 layout with `package.json` is what 7.3+ exports [R].
- **Studio (10):** works in the app over USB; profile support is unclear (section 6). Low priority.
- **Pedal (5), G-Keys (4), Voyager (6), SCUF (8):** no displays, so images don't show [C/I].

## 3. SDK `DeviceType` enum and device events

Verbatim from `elgatosf/schemas` `src/streamdeck/plugins/device-type.ts` (main), identical in
`@elgato/schemas` 0.6.0. `@elgato/streamdeck` 3.0.4 re-exports it from `dist/api/device.d.ts` [C]:

```ts
export enum DeviceType {
	StreamDeck = 0,        // 15 keys, 5 x 3
	StreamDeckMini = 1,    // 6 keys, 3 x 2
	StreamDeckXL = 2,      // 32 keys, 8 x 4
	StreamDeckMobile = 3,
	CorsairGKeys = 4,
	StreamDeckPedal = 5,   // 3 pedals
	CorsairVoyager = 6,    // "10 buttons in a horizontal line above the keyboard"
	StreamDeckPlus = 7,    // 8 keys, 4 x 2, touch strip, 4 dials
	SCUFController = 8,
	StreamDeckNeo = 9,     // 8 keys, 4 x 2, info bar, 2 touch points for page navigation
	StreamDeckStudio = 10, // 32 keys, 16 x 2, 2 dials
	VirtualStreamDeck = 11,// 1 to 64 actions, max 8 x 8
	Galleon100SD = 12,     // 12 keys, 3 x 4, LCD screen, 2 dials
	StreamDeckPlusXL = 13  // 36 keys, 9 x 4, touch strip, 6 dials
}
```

The SDK Devices page lists **"Stream Deck, Stream Deck Scissor Keys"** under 0 [C]. The manifest
schema accepts `Profiles[].DeviceType` from **0 to 13** [C].

When entries arrived (SDK changelog [C]): 6.6 added Neo (9) and SCUF (8). 6.9 added Studio (10).
7.0 added Virtual Stream Deck (11) and `deviceDidChange`, and made device `size` reflect the visual
size ("Previously always 8 x 8 for Stream Deck Mobile and Virtual Stream Deck"). 7.1 "fixed device
type mapping for Stream Deck Scissor Keys and Corsair keyboards". 7.6 added the Neo Infobar and the
`Neo` manifest controller. Galleon (12) and + XL (13) aren't in the SDK changelog; they arrived with
app 7.2.0 and 7.3.0 [R].

### Raw WebSocket device messages (docs: WebSocket API → Plugin) [C]

```json
{ "event": "deviceDidConnect",
  "device": "<device id>",
  "deviceInfo": { "name": "<user-editable name>", "type": 7, "size": { "columns": 4, "rows": 2 } } }
```

- `size` is the "Number of action slots, excluding dials / touchscreens" [C].
- `name` is "Name of the device, as specified by the user", so don't use it to detect the model [C].
- `deviceDidChange` (7.0+) has the same shape. `deviceDidDisconnect` carries only `device` [C].
- The registration info passed at launch has `devices: [{ id, name, size, type }]`, which "may
  include devices that are not currently connected" [C].
- Encoder events (`dialDown`, `dialUp`, `dialRotate`, `touchTap`) carry
  `payload.controller: "Encoder"` and `coordinates {column, row}`. `dialRotate` adds `ticks` and
  `pressed`; `touchTap` adds `tapPos: [x, y]` and `hold` [C].
- `willAppear` / `willDisappear` carry `controller: "Encoder" | "Keypad" | "Neo"` [C].

## 4. What a plugin or icon pack can draw on, and at what size

| Surface | Manifest controller | Canvas | Rules | Source |
|---|---|---|---|---|
| LCD key, manifest image | `"Keypad"` | app scales per device | `States[].Image`: GIF, PNG or SVG; 72×72 and 144×144 @2x | [C] manifest schema |
| LCD key, runtime `setImage` | `"Keypad"` | app scales | path, base64 data URL (PNG/JPEG/WEBP) or SVG (recommended); **no animated formats**; one size only, so send high DPI; **≤10 updates/s** | [C] keys guide, plugin guidelines |
| Icon pack image | – | – | **144×144 required**; SVG/PNG/JPEG static, GIF/WEBP animated, 10–20 fps, ≤5 s, ≤1 MB, file name ≤80 characters | [C] icon pack docs |
| Dial icon (shown in the app) | `"Encoder"` | – | `Encoder.Icon`: PNG/SVG, 72×72 and 144×144 | [C] |
| Touch strip segment (+, + XL) | `"Encoder"` | **200×100 per dial**; "Plugins cannot render across the entire touch strip" | `Encoder.background`: PNG/SVG, 200×100 and 400×200 @2x; layouts `$X1 $A0 $A1 $B1 $B2 $C1` or a custom JSON | [C] dials guide, layouts reference |
| Neo Infobar | `"Neo"` (7.6+) | **232×50** (hardware window 248×58) | layout JSON; `setFeedbackLayout` on every `willAppear`; display only | [C] |
| Neo touch points | – | – | not exposed to plugins | [I] |
| Studio dials and LED rings | – | – | undocumented | [?] |
| Galleon dial/screen area | probably `"Encoder"` [I] | undocumented | – | [?] |
| Pedal, G-keys, S-keys, SCUF | `"Keypad"` | no display | images never shown | [C/I] |

Native key sizes [C, except Studio and Galleon R]: 72 (15-key family), 80 (Mini), 96 (XL, Neo),
112 (+ XL), 120 (+), 144×112 (Studio), 160 (Galleon). A 144 source is downscaled everywhere except
the Galleon, which upscales it slightly. How Studio fits a square image on a 144×112 key isn't
documented [?].

Layout canvases per the docs' Layouts reference [C]: "Stream Deck + — 200 × 100 px; Stream Deck
+ XL — 200 × 100 px; Stream Deck Neo Infobar — 232 × 50 px". The `@elgato/schemas` type comments
only mention "+" and "Neo", but the docs name + XL explicitly.

Layout rules [C]: every item needs a unique `key` (`^[A-Za-z0-9\-_]+$`), a `type`
(`bar`/`gbar`/`pixmap`/`text`) and a `rect`. Items must stay within the bounds, and items on the
same `zOrder` (0–700) must not overlap. If any of these fail, nothing renders. `rect` can't change
at runtime.

Neo Infobar layout, verbatim [C]:

```json
{
    "$schema": "https://schemas.elgato.com/streamdeck/plugins/layout.json",
    "id": "neo",
    "controller": "Neo",
    "items": [
        { "type": "pixmap", "key": "leading", "rect": [10, 15, 20, 20] },
        { "key": "title", "type": "text", "rect": [40, 15, 152, 20], "font": { "size": 15 } },
        { "key": "trailing", "type": "pixmap", "rect": [202, 15, 20, 20] }
    ]
}
```

Built-in `$X1` encoder layout, verbatim [C]:

```json
{
    "$schema": "https://schemas.elgato.com/streamdeck/plugins/layout.json",
    "id": "$X1",
    "items": [
        { "key": "title", "type": "text", "rect": [16, 10, 136, 24], "font": { "size": 16, "weight": 600 }, "alignment": "left" },
        { "key": "icon", "type": "pixmap", "rect": [76, 40, 48, 48] }
    ]
}
```

Manifest controller type [C]: `Controllers?: [Controller, Controller?, Controller?]`, where
`Controller = "Encoder" | "Keypad" | "Neo"`. For any `Software.MinimumVersion` below `"7.6"`, the
schema allows only Encoder/Keypad and at most 2 items. **A `"Neo"` action needs
`MinimumVersion: "7.6"`.**

## 5. Profile `Device.Model` identifiers

### 5.1 Elgato's sample profiles [C]

`elgatosf/streamdeck-plugin-samples` `lights-out/com.elgato.lightsout.sdPlugin/*.streamDeckProfile`,
downloaded and unzipped again for this check. The plugin manifest pairs each file with a `DeviceType`
(`Software.MinimumVersion: "6.5"`):

| File | `DeviceType` | `Device.Model` | Page controllers | Key coordinates |
|---|---|---|---|---|
| `sd` | 0 | `20GAA9901` | Keypad | `0,0` … `4,2` |
| `sd-mini` | 1 | `20GAI9901` | Keypad | `0,0` … `2,1` |
| `sdxl` | 2 | `20GAT9901` | Keypad | `0,0` … `7,3` |
| `sd-mobile` | 3 | `VSD2/WiFi` | Keypad | `0,0` … `7,7` |
| `sdp` | 7 | `20GBD9901` | Keypad + Encoder | `0,0` … `3,1` |
| `sd-neo` | 9 | `20GBJ9901` | Keypad + Neo | `0,0` … `3,1` |

All of them use the 2.0 layout: `<UUID>.sdProfile/manifest.json` with
`{"Device":{"Model":…,"UUID":""},"Name":…,"Pages":{"Current","Default","Pages":[…]},"Version":"2.0"}`,
plus `Profiles/<27-char id>/manifest.json`. Each has 2 page folders: the listed page and the
`Default` page, which is empty [C]. Coordinates are `"column,row"` from the top left.

## 6. Per-device notes

**Stream Deck + (7).** 4×2 keys at 120 px, 4 dials (rotate, push), 800×100 strip split into four
200×100 canvases [C]. The strip reports tap, long press and flick, each once the gesture ends [C, HID].
Trigger description keys are `Push`, `Rotate`, `Touch`, `LongTouch` in the manifest and `push`,
`rotate`, `touch`, `longTouch` at runtime [C]. Profile dial slots are `0,0` … `3,0` [R].

**Stream Deck + XL (13).** 9×4 keys at 112 px, 6 dials, 1200×100 strip (161×14 mm) giving six
200×100 canvases, so encoder layouts carry over from the + unchanged [C]. Elgato's profile docs say
"38 / 4 x 9"; every other Elgato source says 36 [C], so 38 is a typo. USB 3.0 Type-C port
recommended; Windows 11+ / macOS 13+ [C]. Dial centres don't line up with key columns [R, estimated
geometry in `@elgato-stream-deck/core`].

**Stream Deck Neo (9).** 4×2 keys at 96 px. The Infobar (248×58 window, not touch) showed a clock
and page dots until 7.6 [C]. Infobar actions get `willAppear`, `willDisappear`, settings,
resources, Property Inspector, `sendToPlugin` and `titleParametersDidChange`, but no input [C]. The
two touch points page left and right. At HID level they're extra buttons 8 and 9 [C], with no SDK
access [I]. 7.6 added Infobar-sized backgrounds to the app's library [C].

**Stream Deck Studio (10).** 1U rack, 32 keys in a 16×2 grid (144×112 px [R]), 2 dials with LED
rings, NFC reader, Ethernet PoE+ or USB-C [C]. Built for Bitfocus Buttons/Companion; "In USB mode,
it'll work with the Stream Deck app" [C]. Elgato's profile docs: "does not currently support Stream
Deck app profiles" [C]. Treat Studio as icons-first; ship a type-10 bundled profile only if tested.

**Stream Deck Pedal (5).** 3 pedals, no display [C]. Actions only. Tablet Deck's one-press-per-tap
rule still applies [I]. 7.6 shipped new Pedal firmware [C].

**Stream Deck Mobile (3).** Free: 6 keys. Pro: up to 64 keys, custom layouts ("Vertical, horizontal,
or square. All 64 keys or one big button"), multiple keypads depending on device. Up to 10
additional pages. Wi-Fi only; Stream Deck 6.3+ [C]. Elgato's sample profile is 8×8 [C]. Since 7.0,
`size` reports the visual layout instead of always 8×8 [C].

**Virtual Stream Deck (11).** Stream Deck 7.0+, Windows 11 64-bit or later. Up to 8×8 (64 keys) per
panel, several panels, each with its own hotkey; Fixed or Dynamic (opens at the cursor). Unlocked by
a supported Stream Deck or Corsair device connected within the past 30 days, or by Mobile Pro [C].

**Corsair GALLEON 100 SD (12).** The Stream Deck replaces the numpad: 12 LCD keys in 3 columns × 4
rows (160 px), a screen above them and 2 push dials above that [R]. Each dial has 2 layers; holding it
for 3 s switches layer, so there are 4 dial actions, and a white border marks the active layer [R,
Corsair article via search; corsair.com returns 403]. The screen updates only while the Stream Deck
app runs; 7.3.0 fixed it falling back to "hardware mode" [R]. **The canvas plugins get for its dial
actions isn't documented** [?].

**Corsair G-Keys (4), Voyager (6), SCUF (8).** No screens; the app shows their assignments in a
floating Action Bar [C]. Low priority for profiles.

**Modules (6/15/32, 2025).** Bare boards that share the HID families and model numbers of the Mini,
MK.2 and XL 2022 [C], so they're almost certainly types 1, 0 and 2 [I].

## 7. Conflicts and open questions

1. **+ XL model string:** `20GBX9901` [R-weak] vs Elgato's HID page `20GBD9901`. Get one genuine
   + XL export.
2. **Stream Deck + model string:** `20GBD9901` [C], but Aputure's generated pack says `20GBC9901`.
   Treat it as their error unless a genuine export shows otherwise.
3. **Galleon grid:** the SDK enum (columns × rows) and the code agree on 3 columns × 4 rows. Elgato's
   profile docs table (otherwise rows × columns) says "3 x 4". What `deviceInfo.size` actually
   reports is untested [?].
4. **Voyager key count:** SDK "up to 10", hardware page "6 S-Keys".
5. **Studio and profiles:** works in the app over USB, but the profile docs say no profile support;
   type 10 is allowed in the manifest.
6. **Not found:** profile Model strings for Pedal, Scissor, Mini 2022, Studio, Virtual Stream Deck,
   Galleon, Corsair and SCUF. Also not found: the Galleon dial/screen canvas, how Studio fits square
   art on 144×112 keys, the `DeviceType` of the Yamaha CC1 and Corsair mice, and whether a
   double-click import checks `Device.Model` against the connected sibling model.
7. **Profile format:** 7.3+ exports 3.0 with `package.json`; Elgato's bundled samples are 2.0. That
   the app still accepts 2.0 for bundled profiles is inferred from Elgato shipping 2.0 samples on
   `main` [I]. Whether 7.6 imports a hand-made 2.0 file by double-click is untested.

## 8. Also noticed (outside device facts, but affects the build)

- Stream Deck 7.6 on Windows: "hotkeys may not reach elevated processes, such as some games, again."
  Star Citizen normally runs unelevated, but if a player runs it as administrator, the built-in
  Hotkey action from the standalone profiles won't reach it [C quote, I application].
- `@elgato/streamdeck` 3.0.4 itself depends on the npm `ws` package and `engines.node >=20.5.1`
  [C]. The manifest `Nodejs.Version` enum is `"20" | "24" | "26"` (`"20"` only for MinimumVersion
  ≤ 7.0) [C]. A plugin with no dependencies needs a WebSocket client from Node itself. Node 22 and
  later have one built in; Node 20 has it only behind a flag, so set `Nodejs.Version: "24"`
  (MinimumVersion ≥ 7.1) or write a small client on `net`/`http` [I; check in the plugin research].
- The raw WebSocket protocol is still documented in full: WebSocket API → Plugin, including
  `setImage`, `setFeedback`, `setFeedbackLayout`, and `setResources` (7.1+) [C].
